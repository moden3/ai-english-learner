# システム要件定義書

> **ステータス**: v1.2 確定版
> **更新日**: 2026-09-02
> **変更点**: 簡易APIキー認証(sessionStorage)への移行、AI生成機能のハイブリッド化（記事生成と構文解析の分離とモデル使い分け）、エンドポイントの修正

---

## 1. プロジェクト概要

| 項目 | 内容 |
|------|------|
| プロジェクト名 | AIを活用した英語学習Webアプリケーション（仮称: ENG-APP） |
| 目的 | 英語の速読訓練・構文読解（スラッシュリーディング・和訳・構文解説）・重要単語把握をAIで支援する |
| 対象ユーザー | **自分専用（個人利用）** |
| 運用形態 | 個人開発・個人運用（コスト最小化） |
| 認証 | **簡易APIキー認証 (`x-api-key`)**（第三者の不正アクセス・AWS/Gemini課金防止のため） |

---

## 2. 機能要件

### 2.1 コア機能（AI連携・ハイブリッド生成）

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-001 | 英文記事生成 | トピックを指定し、AIを用いて長文の英語記事（ソースURL付き）を生成する（高品質モデルを利用） |
| F-002 | 構文解析・単語抽出 | 生成された英文を対象に、「スラッシュ分割」「セグメント別和訳」「構文解説」「重要単語リスト」を生成する（軽量モデルを利用） |
| F-003 | AIバックエンド連携 | Google Gemini APIを呼び出し、用途に合わせてモデル（1.5-flash / 1.5-flash-lite）を使い分けるハイブリッド方式でデータを取得する |

### 2.2 トピック管理機能

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-004 | トピックリスト取得 | 英文生成で選択可能なトピック一覧を取得する |
| F-005 | トピックランダム選択 | 登録済みトピックの中からランダムに1件を選択して英文生成に使用する（デフォルト動作） |
| F-006 | トピック追加 | ユーザーがトピックリストに新しいトピックを追加する |
| F-007 | トピック削除 | ユーザーがトピックリストからトピックを削除する |

### 2.3 単語帳機能（データ永続化）

| 機能ID | 機能名 | 説明 |
|--------|--------|------|
| F-008 | 単語・フレーズ保存 | 一括生成された重要単語リスト等から、ユーザーが選択した単語・フレーズをDynamoDBに保存する |
| F-009 | 単語帳一覧取得 | 保存済みの単語・フレーズ一覧を取得する |
| F-010 | 単語・フレーズ削除 | 保存済みの単語・フレーズを削除する |

## 3. 非機能要件

### 3.1 パフォーマンス

| 項目 | 目標値 | 備考 |
|------|--------|------|
| コールドスタート時間 | 1秒以内 | Rust採用 |
| API応答時間（P95） | 3〜5秒 | 一括生成のため1回あたりの生成量は増えるが、総待ち時間は劇的に減少 |

### 3.2 コスト目標（極限までの削減）

**目標: 完全月額$0**

- **Gemini API呼び出しのハイブリッド最適化**: 記事の新規生成には高品質モデル (`gemini-1.5-flash`) を、構文・単語の解析には軽量モデル (`gemini-1.5-flash-lite`) を使い分けることでAPI無料枠を最適化。
- **開発・テスト時のトークン節約機能 (実装済)**:
  - **ダミーモード**: ローカル開発時に環境変数や特定のトピック名(`test`)を用いることで、API通信を完全に遮断しダミーテキストを返却。
- **セキュリティ保護**: 簡易APIキー認証により外部からの不正スパムリクエストを遮断し、AWS/Geminiの予期せぬ課金を防ぐ。
