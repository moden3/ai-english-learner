# 5. サーバーレスのコスト最適化戦略

本プロジェクトは **完全月額無料 ($0)** での運用を前提としたアーキテクチャ設計を採用している。

## 1. インフラ基盤の徹底したサーバーレス化
常時起動型のサーバー（EC2/ECSなど）は固定費が発生するため不使用。
- **フルサーバーレス**: `Lambda`, `API Gateway`, `DynamoDB` など、完全にリクエスト駆動のマネージドサービスのみを採用。AWSの毎月リセットされる無料枠（Free Tier）内に収める。

## 2. Gemini API 無料枠の最大化（ハイブリッド方式）
高品質な推論と、厳しい利用上限のジレンマを解決するためのモデル使い分け戦略。

| モデル | 性能・特徴 | 無料枠の上限 | 本アプリでの用途 |
| :--- | :--- | :--- | :--- |
| **1.5-flash** | 高推論、Google検索可能 | 厳しい (数十〜数百回/日) | 記事の新規生成（重い処理） |
| **1.5-flash-lite**| 軽量、高速 | 余裕あり (1500回/日など) | 構文解析、単語抽出（単純処理） |

- **UIからのオプトイン**: 画面上に「高度なAIモデルを使用する」チェックボックス（デフォルトOFF）を設け、ユーザーが意図した時のみ標準モデルを消費する設計。

## 3. Google Search (グラウンディング) の緻密な制御
Geminiの検索機能を有効にすると、専用の極端に厳しいレートリミットが適用されてしまう。
- **検索ON**: 最新情報が必要な「記事生成 (Generate)」のAPI呼び出し時のみ。
- **検索OFF**: すでに生成されたテキストに対する「構文解析 (Analyze)」のAPI呼び出し時は明示的に無効化し、リミット消費を防ぐ。

## 4. 予期せぬ課金（スパムトラフィック）の防止策
- **API Gatewayのキー認証**: 第三者による不正なAPI呼び出し（Lambda起動やGemini APIの浪費）をエッジでブロック。
- **CloudFront OAC**: S3への直接アクセスを遮断。必ずキャッシュを経由させることで、悪意のある大量ダウンロードによるデータ転送料課金を防ぐ。
